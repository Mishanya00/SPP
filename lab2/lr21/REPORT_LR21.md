## 1. Концептуальная модель сложной системы

### 1.1. Содержательное описание объекта моделирования
Объектом моделирования является **станция технического контроля** промышленных изделий. 
Собранные изделия поступают в систему и проходят последовательные испытания на трех специализированных станциях контроля ($S_1, S_2, S_3$). 
- Каждая станция осуществляет проверку изделия.
- При обнаружении брака (дефекта) на любой из трех станций изделие немедленно снимается с испытаний и направляется на участок наладки.
- **Ограничение участка наладки:** одновременно может производиться наладка **только одного изделия**.
- После завершения наладки изделие возвращается на повторные испытания, начиная с первой станции ($S_1$).
- **Критическое условие браковки:** если изделие попадает на наладку вторично, оно считается неисправимым браком и окончательно бракуется.

### 1.2. Сущности, ресурсы и очереди
1. **Объекты (динамические сущности):**
   - `Item` (Изделие) — обладает атрибутами: идентификатор `item_id`, время поступления в систему $t_{arr}$, счетчик обнаруженных дефектов `defect_count` (0, 1 или 2), текущая станция `current_station_idx`, статус (`in_system`, `completed`, `scrapped`).
2. **Обслуживающие аппараты (ресурсы):**
   - `Station 1`, `Station 2`, `Station 3` — одноканальные посты технического контроля.
   - `Repair Station` — одноканальный пост наладки/ремонта.
3. **Очереди (накопители):**
   - $Q_1, Q_2, Q_3$ — очереди ожидания проверки перед станциями 1, 2 и 3 (FIFO).
   - $Q_{repair}$ — очередь ожидания перед постом наладки (FIFO).

### 1.3. Входной поток и начальное состояние
- **Входной поток:** простейший Пуассоновский поток изделий с экспоненциально распределенными интервалами между поступлениями $T_{arr} \sim \text{Exp}(\lambda)$, средний интервал $\bar{T}_{arr} = 10.0$ мин ($\lambda = 0.1$ мин$^{-1}$).
- **Начальное состояние системы ($t = 0$):**
  - Все станции контроля ($S_1, S_2, S_3$) и участок наладки свободны.
  - Все очереди пусты.
  - В календаре событий запланировано первое событие — поступление первого изделия в момент времени $t = T_{arr, 1}$.

### 1.6. Выбор и классификация откликов модели (согласно Слайдам 10–13 лекции)
В соответствии с требованиями программы выбрано **более 4 откликов**, охватывающих все обязательные классы:

1. **Отклики в дискретном времени (Discrete-time responses):**
   - $\bar{T}_{sys}$ — среднее время пребывания изделия в системе от момента входа до выхода (выпуска или браковки). Вычисляется усреднением по числу завершивших обслуживание изделий: $\bar{T}_{sys} = \frac{1}{N}\sum T_i$.
   - $\bar{W}_{rep}$ — среднее время ожидания изделий в очереди на наладку.
   - $P_{scrap}$ — доля окончательно забракованных изделий от общего числа обработанных.
2. **Отклики в непрерывном времени (Continuous-time responses):**
   - $\bar{L}_{q, rep}$ — средняя длина очереди на наладку во времени. Интегральный отклик: $\bar{L} = \frac{1}{T}\sum L_i \Delta t_i$.
   - $\bar{K}_{rep}$ — коэффициент занятости (загрузки) поста наладки.
   - $\bar{L}_{q, st}$ — средняя суммарная длина очередей перед станциями контроля.
   - $\bar{N}_{sys}$ — среднее число изделий, одновременно находящихся в системе.
3. **Аддитивные отклики (Additive responses):**
   - $N_{arr}$ — суммарное число поступивших изделий.
   - $N_{good}$ — общее количество успешно изготовленных годных изделий.
   - $N_{scrap}$ — общее количество забракованных изделий.
   - $N_{repairs}$ — суммарное число выполненных наладок.
4. **Финальные отклики (Final responses):**
   - $T_{fin}$ — фактическое модельное время завершения прогона с учетом фазы дообслуживания (clearance mode).

## 2. Программная имитационная модель

### 2.1. Алгоритм квазипараллелизма
Имитационная модель построена на основе алгоритма **расписания (планирования) событий (Event Scheduling)**, являющегося классическим методом дискретно-событийного моделирования (DES):
- Список будущих событий (Future Event List, FEL) реализован на основе структуры данных двоичной кучи (`heapq`), упорядоченной по возрастанию модельного времени наступления событий $t_{event}$.
- Время моделирования изменяется **скачкообразно** от текущего события к ближайшему следующему.
- **Строгое выполнение требования:** алгоритм с постоянным временным шагом ($\Delta t = \text{const}$) **не используется**, шаг моделирования полностью определяется динамикой наступления событий.

### 2.2. Генератор случайных чисел
Для всех случайных потоков (генерация интервалов времени, моделирование длительностей проверок и наладки, розыгрыш вероятностей брака) используется **единственный стандартный экземпляр датчика псевдослучайных чисел** языка Python (`random.Random(seed)`), что обеспечивает полную воспроизводимость результатов любого эксперимента.

### 2.3. Режим трассировки
В модели предусмотрен подробный режим трассировки (`--trace`), протоколирующий каждый шаг квазипараллельного процесса с указанием текущего модельного времени, типа события, идентификатора изделия и текущего состояния очередей.
