# Автобот

Веб-приложение для создания Telegram-ботов по текстовому описанию через DeepSeek.
Восстановлено из работающего контейнера `lab2-app-1` 7 октября 2026 года.
Исходная папка: `/home/mishanya00/Education/University/Sem7/SPP/lab2`.

## Что восстановлено

- `server/`: исходный сервер Node.js, авторизация, генерация, управление ботами и логи.
- `runner/`: валидатор сгенерированного Python и исходный загрузчик ботов.
- `dist/`: готовый интерфейс. Исходники React/TypeScript, конфигурация Vite и оригинальные тесты в контейнере отсутствовали.
- `package.json`, `package-lock.json`, `node_modules/`: оригинальные зависимости и установленная production-копия.
- `data/`: согласованная копия SQLite, ключ шифрования и сохранённый код ботов.
- `.env`: параметры работающего контейнера; значения ключей не выводились при восстановлении.
- `Dockerfile`, `runner/Dockerfile`, `compose.yaml`: заново составленные файлы запуска по коду и метаданным образов.
- `RECOVERY.json`: сведения об источнике восстановления.

Исходный `package.json` сохранён без изменений. Команды `dev` и `build` ссылаются на отсутствующие исходники; для текущей восстановленной версии используйте `start` и готовый `dist/`. Оригинальные тесты отсутствуют; `npm test` запускает добавленные проверки диагностики ошибок генерации.

## Запуск с восстановленными данными

На этой машине оставлены готовые образы `autobot-app:recovered` и `autobot-runner:local`.
Порт 3000 сейчас занимает исходный контейнер. Для перехода на восстановленный проект:

```sh
docker stop lab2-app-1
cd /home/mishanya00/Education/University/Sem7/SPP/Autobot
docker compose up -d
```

Не запускайте два экземпляра сервера одновременно: они управляют одними и теми же контейнерами `autobot-*`.
Восстановленная `data/` — снимок на момент извлечения; изменения, сделанные позднее в старом приложении, в эту копию не попадут.
Открывайте http://localhost:3000. Данные пользователей и ботов сохранены вместе с ключом шифрования.

Для пересборки образов после изменения серверного кода:

```sh
docker compose build
docker compose up -d
```

Для запуска сервера без контейнера нужны Node.js 22.23.3, Python 3 и доступный Docker CLI:

```sh
npm start
```

Сервер использует `./data` и отдаёт готовый интерфейс из `./dist`.
При переносе на другую машину установите production-зависимости через `npm ci --omit=dev` и соберите образы.
Существующие тома отдельных Telegram-ботов остались в Docker этой машины; в `data/` находится код и база приложения, а не содержимое всех томов ботов.

## Ошибка подключения к DeepSeek

`fetch failed` означает сбой сетевого запроса. Сервер сохраняет вложенную причину на вкладке «Логи» и в ошибке бота: например, `EAI_AGAIN`/`ENOTFOUND` для DNS, `ETIMEDOUT`/`UND_ERR_CONNECT_TIMEOUT` для таймаута подключения или `ECONNRESET` для сброса соединения. HTTP-ошибки выводятся отдельно с подсказкой: 401 — ключ, 402 — баланс, 429 — лимит запросов.

Проверяйте доступ именно из контейнера приложения. Следующая команда не передаёт ключ и не запускает генерацию; HTTP 401 здесь подтверждает получение ответа от API:

```sh
docker compose exec app node --input-type=module -e 'try { const r = await fetch("https://api.deepseek.com/models", { signal: AbortSignal.timeout(15000) }); console.log("HTTP", r.status); await r.body?.cancel(); } catch (e) { console.error(e.message, e.cause); process.exitCode = 1; }'
```

Если VPN/Mihomo/Clash подменяет DNS адресами `198.18.x.x`, подключение зависит от его TUN-маршрута. При сбое проверьте активность TUN и выбранный маршрут для `api.deepseek.com`; сравните доступ из контейнера и с хоста. После исправления соединения используйте повторную генерацию в существующем проекте.

Ошибка «Этот Telegram-бот уже подключён» независима от DeepSeek: `telegram_id` уникален в базе. Используйте существующий проект с этим Telegram-ботом либо другой токен. Если старый проект больше не нужен, его можно удалить через интерфейс, после чего привязать токен к новому.

## Формат ответа генерации

Для `deepseek-flash` и `deepseek-v4-pro` сервер явно отключает thinking, чтобы бюджет ответа расходовался на JSON с кодом. Промпт содержит пример JSON и правила экранирования Python-кода. Перед разбором сервер проверяет `finish_reason` и наличие текста: пустой ответ и ответ, обрезанный по лимиту токенов, имеют отдельные сообщения об ошибке. Полный JSON внутри markdown-блока также принимается; повреждённый или обрезанный код не восстанавливается автоматически.

В журнал записываются причина завершения, длины текста и рассуждений и число токенов ответа. Само содержимое ответа в диагностические записи не попадает.

Если ответ не проходит разбор JSON или проверку Python, сервер автоматически отправляет в DeepSeek предыдущий ответ и конкретную ошибку проверки. После каждой правки код проверяется заново. Разрешены первоначальная генерация и до трёх автоматических исправлений; до успешной проверки проект остаётся в состоянии генерации и бот не запускается. Сетевые ошибки, HTTP-ошибки и недоступность валидатора прекращают эту операцию без повторной отправки кода.

Валидатор проверяет только синтаксис Python: ограничений на импорты, комментарии, кавычки и наличие inline-кнопок нет. В образе бота установлены aiogram и его зависимости, включая aiohttp; вся стандартная библиотека Python доступна. Произвольные сторонние пакеты автоматически не устанавливаются.

Ботам, код которых использует переменные `DEEPSEEK_*`, при запуске передаются `DEEPSEEK_API_KEY`, `DEEPSEEK_BASE_URL` и `DEEPSEEK_MODEL` из настроек сервера. Остальные боты получают только `BOT_TOKEN`. Значения ключей передаются через окружение Docker CLI, не через аргументы команд; загрузчик скрывает оба ключа в выводе. Вызовы DeepSeek из ботов используют серверный ключ и его баланс.
