Как устроен Автобот

Автобот — веб-приложение, которое создаёт Telegram-ботов по текстовому описанию. Пользователь описывает нужное поведение, DeepSeek генерирует Python-код, а приложение проверяет его и запускает в отдельном Docker-контейнере.

Сервер сохраняет проект в SQLite и запускает Python-бота в Docker.
Запущенный бот получает сообщения из Telegram и отвечает через Telegram API.

Из каких частей состоит система

ИнтерфейсReact и TypeScript. Пользователь регистрируется, описывает бота, добавляет Telegram-токен, смотрит состояние, код и логи, запускает или останавливает проект.
СерверNode.js и Express. Принимает запросы интерфейса, проверяет права пользователя, обращается к DeepSeek и Telegram, управляет контейнерами через Docker CLI.
ХранилищеSQLite содержит пользователей, сессии, проекты, сгенерированный код и журналы. Каталог data/ сохраняет базу, ключ шифрования и файлы проектов.
Среда ботовОтдельный контейнер на Python 3.12 с aiogram 3 для каждого бота. Общий образ содержит необходимые зависимости и загрузчик Python-кода.

Что происходит при создании бота

  1. Описание сохраняется. Сервер создаёт проект со статусом «генерируется». Интерфейс получает ответ сразу; долгая генерация продолжается в фоне.
  2. Составляется запрос к DeepSeek. Системный промпт объясняет среду запуска, работу с токенами и формат результата. Пользовательское описание задаёт функциональность.
  3. Модель возвращает JSON с названием и кодом. Сервер разбирает ответ, записывает main.py и проверяет синтаксис Python.
  4. Ошибки исправляются автоматически. Если JSON или код некорректны, предыдущий ответ и ошибка отправляются модели. Возможны первоначальная генерация и до трёх исправлений.
  5. Проект становится готовым. Если Telegram-токен уже добавлен, начинается запуск. Иначе приложение предлагает добавить его.

Важно: синтаксическая проверка обнаруживает ошибки языка, но не гарантирует правильность поведения. После запуска работу бота нужно проверить в Telegram.

Запуск и работа ботов

Как бот связывается с Telegram

Пользователь создаёт Telegram-бота через BotFather и добавляет его токен в Автобот. Сервер проверяет токен методом getMe и не разрешает привязать одного Telegram-бота к нескольким проектам.

При запуске сервер обновляет профиль бота, отключает webhook, копирует код в отдельный том и создаёт контейнер. Токен передаётся через переменную окружения BOT_TOKEN. Затем aiogram запускает long polling: регулярно запрашивает у Telegram новые сообщения и передаёт их подходящим обработчикам.

Обработчики отвечают на команды, текст, фото и нажатия кнопок. Для многошагового диалога используются состояния FSM: бот запоминает, какого ответа он сейчас ожидает.

Две роли DeepSeek

При создании DeepSeek пишет и исправляет исходный код. Во время работы он нужен только тем ботам, которым требуются AI-ответы, например Пушкин-боту. Обычный бот с меню или фиксированными ответами работает без обращения к модели.

Ботам, использующим DeepSeek, сервер передаёт DEEPSEEK_API_KEY, DEEPSEEK_BASE_URL и DEEPSEEK_MODEL. Их обращения используют серверный ключ и его API-баланс.

Данные, изоляция и контроль

  • Данные переживают остановку. Код и данные бота находятся в отдельных Docker-томах. Код доступен только для чтения; рабочие данные сохраняются в /data. При перезапуске теряется лишь состояние в памяти.
  • Каждый бот работает отдельно. Контейнер ограничен по памяти, CPU и числу процессов, запускается без прав root. Проверяется только синтаксис кода; разрешены стандартная библиотека, комментарии и любой стиль кавычек.
  • Секреты защищаются. Пароли хешируются с scrypt, Telegram-токены шифруются с AES-GCM. Ключи передаются через окружение, а в журналах скрываются.
  • Состояние отслеживается. Проект проходит этапы «генерируется → готов → запущен». При остановке получает статус «остановлен», при сбое — «ошибка». Сервер проверяет работающие контейнеры каждые 10 секунд; события и вывод Python доступны в логах.

Как объяснить проект за минуту

«Автобот создаёт Telegram-ботов по описанию на сайте. Сервер просит DeepSeek написать Python-код, проверяет его и отправляет ошибки модели на исправление.

После добавления токена от BotFather бот запускается в отдельном Docker-контейнере. Через aiogram он получает сообщения Telegram и отвечает на них. Сайт позволяет управлять ботом и смотреть логи, а SQLite и Docker-тома сохраняют проекты и данные. Если боту нужны AI-ответы, он обращается к DeepSeek во время диалога».
