# АТЛАС — космическая игра

Лабораторная №4: многопользовательская игра на чистом JavaScript, вдохновлённая атмосферой «Космических рейнджеров». HTML/CSS/SVG и браузерный WebSocket API на клиенте, Node.js и библиотека `ws` на сервере. Фреймворков и сборщика нет. Графика создана средствами CSS и SVG; ассеты оригинальной игры не используются.

## Быстрый запуск

Нужен Node.js 22 или новее. Из корня репозитория:

```sh
cd Lab4
npm ci
npm start
```

Открыть **http://localhost:3000**. Зарегистрировать капитана (имя 3–20 символов, пароль 8–128 символов), выбрать расу. Для второго игрока открыть другой браузер или приватное окно. Обычные вкладки одного браузера используют один аккаунт; несколько сессий одного капитана тоже поддерживаются.

`npm run dev` перезапускает сервер после изменения исходников. `npm run check` проверяет синтаксис; `npm test` запускает тесты правил и интеграционный сценарий с настоящими WebSocket-клиентами. Интеграционному тесту нужен доступ к локальному порту.

## Первый рейс

1. В родной системе принять заказ в панели справа. На карте цель заказа обозначается квадратной рамкой.
2. Открыть «Мои заказы» (вторая кнопка слева), нажать название пункта назначения.
3. Нажать «Гиперпрыжок». Корабль летит несколько секунд, другие капитаны видят его перемещение.
4. По прибытии открыть «Мои заказы» и нажать «Сдать груз».
5. В разделе корабля или на вкладке «Обслуживание» заправиться, отремонтироваться, улучшить корабль.

Все системы доступны через промежуточные прыжки. Принять можно до трёх заказов с учётом вместимости трюма. Топливо списывается в момент отправления; перелёт не расходует HP. Заправка и ремонт стоят по 3 кредита за единицу. Улучшение увеличивает трюм на 8 т, дальность на 35 св. л., максимальное здоровье на 8. Всего пять улучшений. Аварийная помощь при недостатке топлива или критическом повреждении доступна даже без денег, поэтому игрок не может застрять навсегда.

Заказы без таймера, груз не пропадает, пока игрок офлайн. При доставке или отмене общий заказ заменяется новым на исходной станции. Это небольшой торгово-исследовательский прототип: NPC-противников и планетарных квестов пока нет; PvP доступно вне стартовых систем.

| Раса | Стартовая система | Кредиты | Корабль | HP | Трюм | Дальность |
| --- | --- | --- | --- | --- | --- | --- |
| Люди | Солнце | 1000–1400 | Странник | 32 | 32 т | 285 |
| Малоки | Трон | 650–950 | Бастион | 38 | 38 т | 260 |
| Пеленги | Пхедок | 1200–1700 | Тень | 28 | 28 т | 300 |
| Фэяне | Фэя | 800–1150 | Спектр | 30 | 30 т | 340 |
| Гаальцы | Краа | 900–1250 | Гармония | 42 | 42 т | 280 |

Качество корабля определяется характеристиками расы; начальная сумма случайна в указанном диапазоне. Пеленги и фэяне летают быстрее, малоки и гаальцы — немного медленнее людей.

## Выполнение требований

| Требование | Реализация |
| --- | --- |
| Многопользовательская игра в реальном времени | Сервер рассылает состояние всем подключённым капитанам после каждой операции; на карте видны корабли и перелёты других игроков. |
| Только JavaScript, без фреймворков | Нативные DOM/SVG/WebSocket, Node HTTP; `ws` используется только как библиотека протокола. |
| Сохранение между запусками | `data/galaxy.json`: аккаунты, сессии, деньги, корабли, заказы, перелёты, журнал. Изменения сначала сохраняются, затем публикуются клиентам. |
| Конкурентный доступ | Сервер последовательно обрабатывает синхронные транзакции. Заказ проверяется и закрепляется за игроком в одной транзакции. Проигравший получает понятный отказ и свежее состояние. Ревизия игрока защищает от устаревших команд из другой вкладки. |
| Потеря соединения | Последний снимок и неподтверждённая команда сохраняются в `localStorage`. Автоматическое переподключение с задержкой 1–10 секунд. Команда повторяется с прежним ID: сохранённая квитанция предотвращает двойной эффект. Новые игровые действия отключаются до синхронизации. |
| Офлайн-перезагрузка | Service Worker кэширует оболочку после первого успешного визита на localhost/HTTPS. Последнее состояние можно открыть без сети; продолжить игру — после восстановления связи. API и пароли не кэшируются. |
| Развёртывание | Подготовлены Dockerfile, Compose и ручной workflow GitHub Pages. Публичная публикация и ссылка ещё не созданы. |

Карта фиксирована и одинакова у всех игроков: 50 звёзд, по 10 на цивилизацию. На старте существует 150 общих грузовых заказов. Геометрия и UI-расчёты находятся в `public/shared.js`, но решения о деньгах, грузе и перелётах принимает только сервер.

### Сохранения и ограничения

Сервер пишет временный файл с `fsync`, затем атомарно заменяет сохранение через `rename`. При ошибке записи исходное состояние остаётся неизменным; повреждённое сохранение не заменяется пустым миром. Для резервной копии остановить сервер и скопировать `data/galaxy.json`. Этот файл содержит хеши паролей и не должен публиковаться.

Пароли хешируются `scrypt` с уникальной солью. Сервер хранит SHA-256-хеши случайных токенов сессий; срок сессии — 30 дней. Пароли и сессии не попадают в игровые снимки. В браузере сохраняется токен входа, поэтому на общем устройстве следует выходить из аккаунта. Публичный сервер должен работать через HTTPS/WSS.

Хранилище рассчитано на **один процесс/один экземпляр сервера** и небольшой учебный мир. Нельзя запускать несколько серверов на одном файле или масштабировать сервис в несколько реплик. Для больших нагрузок потребуется БД с транзакциями и координация между процессами. Прокси и хостинг должны поддерживать WebSocket Upgrade; диск с данными должен быть постоянным. Лимит попыток входа использует IP непосредственного соединения, поэтому за общим прокси он может объединять посетителей.

Полёт хранит серверное время прибытия. Если сервер перезапущен или игрок вышел во время перелёта, прибытие фиксируется после запуска сервера. При отсутствии связи экран не выдумывает новые результаты: показывает последнее подтверждённое состояние.

## Публикация

GitHub Pages публикует статические HTML/CSS/JS и **не запускает Node.js/WebSockets** ([официальная документация](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)). Поэтому есть два варианта.

### Вариант 1: вся игра на одном сервере

Самый простой вариант: разместить `Lab4` на сервере с Node.js 22 и постоянным диском, выполнить `npm ci --omit=dev` и `npm start`. Клиент и WebSocket обслуживаются одним приложением. `public/config.js` остаётся без изменений.

Для Docker из папки `Lab4`:

```sh
docker compose up --build -d
```

Игра доступна на порту 3000, сохранение — в постоянном томе `galaxy`. Не удалять том при обновлении контейнера. Для публичного доступа настроить домен и HTTPS reverse proxy с поддержкой WebSockets либо использовать соответствующие возможности хостинга.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | HTTP и WebSocket порт |
| `DATA_DIR` | `Lab4/data` | Папка постоянного сохранения; в контейнере `/app/data` |
| `ALLOWED_ORIGINS` | пустая строка | Дополнительные разрешённые origin клиентов через запятую, без пробелов и завершающего `/` |

Проверка готовности: `GET /api/health`. Для локального интерфейса origin текущего сервера разрешён автоматически.

Если на HTTP-адресе сервера вход работает, но все действия молча игнорируются, проверить консоль браузера. Ошибка `crypto.randomUUID is not a function` указывает на старую версию клиента: этот API доступен только в защищённом контексте, включая исключение для localhost. В текущей версии для HTTP предусмотрена генерация ID через `crypto.getRandomValues`. Обновить исходники на сервере и перезагрузить страницу с очисткой кэша (`Ctrl+Shift+R`). Сохранение `data/galaxy.json` удалять не нужно. Офлайн-кэш Service Worker по обычному HTTP за пределами localhost недоступен; для него нужен HTTPS.

### Вариант 2: клиент на GitHub Pages, сервер отдельно

1. Разместить сервер по варианту 1 и получить его **HTTPS origin**, например `https://atlas.example.com`. Нужен постоянный диск и один экземпляр приложения.
2. На сервере установить `ALLOWED_ORIGINS=https://USERNAME.github.io`, где `USERNAME` — владелец репозитория. Это origin без `/REPOSITORY`, даже если игра находится по адресу с именем репозитория. Перезапустить сервер.
3. Загрузить проект в GitHub, включая `.github/workflows/lab4-pages.yml` из корня этого репозитория. При переносе одной папки `Lab4` в отдельный репозиторий нужно скорректировать пути `Lab4/public` в workflow.
4. В **Settings → Pages → Source** выбрать **GitHub Actions**.
5. В **Actions → Publish Lab4 Star Atlas → Run workflow** указать HTTPS origin сервера в поле `server_url`.
6. Workflow подставит адрес в клиентскую конфигурацию и опубликует только `Lab4/public`. Адрес страницы появится в результате deployment. Открыть его в двух браузерах, пройти рейс, проверить переподключение.

Workflow запускается вручную и не публикует сайт при обычном push. Он разворачивает клиент как Pages-сайт всего репозитория: если там уже есть другой сайт, выбрать отдельный репозиторий. Настройка выполнена по [официальному руководству GitHub Actions для Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

При другом статическом хостинге скопировать содержимое `public/` и вручную задать `window.STAR_ATLAS_SERVER = 'https://atlas.example.com';` в `config.js`. Относительные ссылки позволяют размещать клиент в подпапке.

## Проверка перед сдачей

1. Запустить `npm run check` и `npm test`.
2. Зарегистрировать двух игроков одной расы в разных браузерах и одновременно принять один заказ: победитель должен быть один.
3. Выполнить доставку. Счёт, груз и журнал обновятся; другой игрок увидит изменения положения корабля.
4. Отключить сеть в DevTools, убедиться в появлении баннера, включить сеть. Игрок получает актуальное состояние без повторного списания.
5. Перезапустить сервер. Войти тем же капитаном и проверить сохранение.
6. После самостоятельного развёртывания приложить к отчёту публичную ссылку. До этого дополнительный пункт о хостинге не считается выполненным.

## PvP и оружие

На каждой станции можно купить до пяти улучшений оружия. Стартовое оружие наносит 2–4,5 HP/с. Каждое улучшение добавляет 1,5 к минимальному и 2,5 к максимальному DPS; цена — 650 + 500 × число купленных улучшений.

Верхняя часть правой панели показывает HP, оружие и корабли в текущей системе. Нажать «Атаковать» для начала боя; «Выбрать» переключает цель. Каждый корабль стреляет только в одну цель. Защищающийся автоматически выбирает нападающего; после исчезновения цели выбирает другого противника. Несколько кораблей могут одновременно атаковать одного. Выход из аккаунта или потеря сети не прекращают начатый бой.

Урон рассчитывается сервером: случайный DPS из диапазона оружия выбирается каждую секунду, затем интегрируется за реально прошедшее время с шагом не более 100 мс. Огонь всех кораблей в одном шаге одновременный. После команды прыжка ещё ровно 400 мс продолжается обмен уроном в исходной системе, затем корабль исключается из боя. Ограничения топлива и дальности остаются, ограничения по минимальному HP для прыжка нет. Ремонт, аварийная помощь, заказы и покупки во время боя недоступны.

Солнце, Пхедок, Краа, Трон и Фэя безопасны для всех рас. Максимальные HP равны вместимости трюма: повреждения уменьшают текущие HP, но не вместимость и не груз. При уничтожении игрок немедленно получает стартовый корабль и оружие своей расы в родной системе. Улучшения и груз теряются; заказы возвращаются в оборот. Кредиты, статистика и аккаунт сохраняются.

Старое сохранение автоматически переводится в версию 2 с сохранением относительного здоровья, капитала, заказов и улучшений корабля. Бои сохраняются между запусками; время выключенного сервера считается паузой и не наносит накопленного урона.
